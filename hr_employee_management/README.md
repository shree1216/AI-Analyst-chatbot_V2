# HR Employee Management - Excel VBA

Open `HR_Employee_Management.xlsm` in desktop Microsoft Excel on Windows.
Enable macros only if you trust this locally built workbook and your organization's
policy permits it. On **Dashboard**, click **Open Employee Manager**.
Excel for the web does not run VBA UserForms.

## Features

- 100 synthetic employees in the protected `Employees` table.
- A wine/charcoal dashboard with live headcount, active employees, leave counts,
  average salary, department summaries, status shares, and a department chart.
- An Employee Manager UserForm with add, search, update, delete, clear, and close.
- Search by employee ID, name, department, job title, email, or status.
- Select a search result to load its details before updating or deleting.
- Confirmation dialogs for add, update, and delete, plus validation messages.
- Dropdowns populated from the `Lists` sheet.

All form fields are required. Phone numbers must contain exactly 10 digits.
Hire dates use `dd-mmm-yyyy` (for example `15-Jan-2024`) and must fall between
1980 and today. Salary must be positive, no greater than 10,000,000, and entered
without commas. Email addresses must be unique.

The Employees sheet is protected without a password to discourage accidental
edits; this is not an access-control or data-security mechanism.

## Rebuild and validate

Close this workbook first, then run from the project root:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\hr_employee_management\build_workbook.ps1
```

**Rebuilding replaces the workbook using `employees.csv`; it does not preserve
records edited in an existing workbook. Back up your workbook first.**

Building requires desktop Excel. The script temporarily enables **Trust access
to the VBA project object model** for the current user, then restores its prior
setting after the build process exits. It does not change macro execution settings.
Do not run concurrent builds.

The build runs 33 checks in Excel before saving. These cover UserForm
initialization, dropdowns and initial button states, invalid inputs, duplicate
email rejection, add/search/update/delete, leading-zero phone preservation,
dashboard recalculation, sheet protection, and unchanged original records.
The test employee is removed. A failed check prevents saving the new workbook.

## Source files

- `modEmployees.bas`: employee data operations and validation.
- `frmEmployee_code.txt`: UserForm events and input handling.
- `modBuildForm.bas`: build-time UserForm designer.
- `ThisWorkbook_code.txt`: workbook-open behavior.
- `EmployeeWorkbookTests.bas`: build-time integration checks.
- `build_workbook.ps1`: workbook assembly and validation.
- `frmEmployee.frm` and `frmEmployee.frx`: exported form, regenerated by the build.

The build-only designer and test modules are removed from the finished workbook.
